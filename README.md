# OC Fate Loom · 命运织机

一个以双角色能动性和可验证叙事关系为核心的命运编织工作台。

它不是把标签串成一句看似合理的话。每一条可见连线都来自选项级规则，并明确区分：支持、张力、冲突、开放问题与真正因果。

> 当前阶段：离线结构预览。没有接入任何模型、供应商、站主 Key 或访客 Key。

## 设计原则

- **两个人都拥有命运。** 内部数据使用对称的角色 A / 角色 B；默认中文预设以“她 / 他”呈现。
- **关联不冒充因果。** 只有选项语义足够时才显示因果；无法判断的部分明确标记为开放问题。
- **张力不等于错误。** 高张力组合会说明需要补写的边界、后果或转折。
- **闭合不是装饰。** 所有已激活路径被承接、且不存在阻断冲突时，命运路径才会标记为闭合。
- **离线预览诚实命名。** 当前结果是结构预检，不冒充大模型写出的场景或成稿。

## 三种生成路线

| 路线 | 当前状态 | 边界 |
|---|---|---|
| 离线结构预检 | 可用 | 浏览器内运行，无网络请求 |
| 站点体验 | 关闭 | 将来只提交受限结构数据到站主 relay；模型与 Key 固定在服务端 |
| 自带密钥 | 关闭 | 将来只允许 Key 直达经过审核并明确展示的供应商域名 |

默认体验与 BYOK 使用完全不同的契约，不共享 Key、prompt 或 transport。

## 本地开发

要求 Node.js `^20.19.0` 或 `>=22.12.0`，并使用 pnpm 10。

```bash
pnpm install --frozen-lockfile
pnpm dev
```

完整检查：

```bash
pnpm check
```

## 项目结构

```text
src/
├── domain/   # 双角色内容数据、选项级规则、DAG 与闭合判定
├── app/      # 状态、草稿隐私、离线结构预检与配置导出
├── api/      # 默认 relay / BYOK 的空置安全契约
├── ui/       # DOM 与因果图组件
├── main.ts   # 界面组合
└── styles.css
```

## 隐私

- API Key 不进入应用状态，不写入浏览器存储、URL、Cookie 或日志。
- 草稿默认不保存；访客主动开启后，轴选择、备注、模型标识等才会保存在本地，并可随时停止与清空。
- 离线结构预检不发送任何网络请求。

更完整的信任边界见 [`docs/security.md`](docs/security.md) 与 [`docs/api-boundaries.md`](docs/api-boundaries.md)。
